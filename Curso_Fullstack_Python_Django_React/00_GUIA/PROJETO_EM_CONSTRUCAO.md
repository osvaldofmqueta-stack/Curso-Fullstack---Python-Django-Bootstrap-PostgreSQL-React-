# Projeto em construção — do catálogo ao GestorWeb

## A aplicação que vamos construir

Não vais estudar tecnologias isoladas. Todas as aulas contribuem para a mesma aplicação.

O projeto começa como:

```text
Catálogo Web
```

E evolui para:

```text
GestorWeb — sistema de gestão para pequenos negócios
```

## A evolução visual do projeto

```text
FASE 1
Catálogo de produtos
        ↓
FASE 2
Catálogo com login, CRUD e relatórios
        ↓
FASE 3
Gestão com PostgreSQL e API Django
        ↓
FASE 4
Frontend React ligado à API
        ↓
FASE 5
GestorWeb publicado e apresentado no portfólio
```

## O que o utilizador final verá

### No início

```text
Navbar
 └── Produtos
      ├── Portátil
      ├── Monitor
      └── Teclado
```

### A meio do curso

```text
Área pública
 ├── Lista de produtos
 ├── Pesquisa
 └── Detalhe do produto

Área protegida
 ├── Dashboard
 ├── Criar produto
 ├── Editar produto
 ├── Relatório Excel
 └── Relatório PDF
```

### No final

```text
GestorWeb
 ├── Dashboard
 ├── Clientes
 ├── Produtos e serviços
 ├── Vendas ou reservas
 ├── Relatórios
 ├── Utilizadores e permissões
 └── Configurações
```

## O que cada etapa acrescenta

| Etapa | O utilizador vê | O que estás a aprender |
|---|---|---|
| Aulas 1–2 | Admin com produtos | Projeto, models e base de dados |
| Aulas 3–5 | Catálogo no navegador | HTML, CSS, Bootstrap, views e templates |
| Aulas 6–8 | Gestão protegida | Forms, CRUD, login e testes |
| Aulas 9–11 | Indicadores e downloads | ORM, dashboard, Excel e PDF |
| Aulas 12–15 | Backend profissional | PostgreSQL, segurança e API |
| Aulas 16–20 | Interface moderna | JavaScript, React e integração |
| Aulas 21–28 | Produto completo | Planeamento, qualidade, deploy e portfólio |

## Regra de motivação

No final de cada aula, deves conseguir apontar para algo novo na aplicação:

```text
“Antes eu só via dados no Admin.
Agora tenho uma página.”

“Antes eu só listava produtos.
Agora consigo pesquisar e filtrar.”

“Antes só eu conseguia usar o sistema.
Agora existem contas e permissões.”

“Antes o catálogo era local.
Agora tenho API, React e publicação.”
```

## Critério para avançar

Não avances só porque leste o documento. Avança quando:

- O resultado da aula aparece na aplicação.
- Consegues explicar o fluxo sem decorar.
- Fizeste o exercício principal.
- Tentaste o desafio.
- Registaste pelo menos um erro e a sua solução.

## Projeto final

No final, o GestorWeb deverá demonstrar:

- Backend Django.
- PostgreSQL.
- Login e permissões.
- API REST.
- Frontend React.
- CRUD.
- Relatórios.
- Exportação Excel e PDF.
- Testes.
- Segurança.
- Deploy.

Esse projeto será o teu primeiro trabalho completo para portfólio. Não precisa de ter todas as funcionalidades de uma empresa real; precisa de mostrar que sabes pensar, construir, testar e publicar uma solução.
