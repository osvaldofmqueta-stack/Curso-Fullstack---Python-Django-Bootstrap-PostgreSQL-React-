## Limite honesto da revisão

Os wireframes são desenhos de orientação e não screenshots de uma aplicação em execução. Não é correto afirmar que todos os ecrãs reais estão validados antes de o projeto ser construído. Depois de implementar cada marco, devemos comparar o resultado real com os wireframes e corrigir diferenças.

Também é necessário executar os exemplos no projeto Django para validar versões de bibliotecas, URLs e detalhes do ambiente. O material foi organizado para essa validação progressiva, mas a construção da aplicação é uma etapa separada.

## Critério de conclusão de cada aula

Uma aula só fica verdadeiramente concluída quando:

1. O código foi executado.
2. O resultado visual foi aberto no navegador.
3. O exercício foi realizado.
4. O desafio foi tentado.
5. Os testes ou verificações passaram.
6. Um screenshot real foi guardado no marco correspondente.
